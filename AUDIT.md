# Source and execution provenance

The dissertation governs historical findings. The public demonstration uses author-released original Study 1 brand data and an illustrative modern rerun. Study 2 individual-user data are not released.

The full cohort is 5,872 records from 11 brands. One blank tweet text is retained there and excluded in the 5,871-row analysis file. The separately prepared lockdown discovery file contains 704 nonempty texts. The quickcheck verifies hashes and reconstructs the full cohort from the minimized collection release. See `docs/data/README.md` and `docs/data/study1/manifest.json` for preparation, counts and archived-source hashes. Minor printed Table 1 name/count pairings differ from the recovered CSV and summary workbook; original documents remain unchanged.

The modern 50-draw discovery run retains 1,200 candidate results and selects five topics with c_v 0.7803344 and 433/704 outliers. It is a measured illustration, not a claim of identical historical findings. Topic models and LLMs include probabilistic steps; different random seeds, models or software versions can change outputs. Published seven-topic/five-theme findings remain labeled as reported.

The ten files in `source-integrity.json` remain byte-identical. The maintained methods HTML/PDF is a separate edition connecting the dissertation method to current code. The guide indexes public source text and current repository documentation; it cannot execute analyses or approve research.

No final historical benchmark, model pickle or naming ballots are asserted by the data release. Research workflows require actual researcher review and independent validation. Live examples are illustrative. Legacy synthetic data and measured synthetic runs remain engineering fixtures, not the primary demonstration or a substitute for human annotations.

The public service uses server-side credentials, atomic spending reservations and bounded released-data calls. Current controls: $20/UTC day, $620/calendar month, 200 session calls and 600 shared-network calls per UTC day. Deployment records are historical snapshots; the active configuration and public API config describe the current release.
