TopicLLM turns a collection of text into candidate topics, researcher-defined themes and measurable patterns. Explore the original Study 1 data here, then take the same workflow into a fork or Python environment.

Start with the actual study data.

The package includes 5,872 original brand records, a 704-text discovery input and the exact stopwords. The demonstration is an illustrative rerun: probabilistic steps and changes in seeds, models or software can produce different topics and labels.

1. Install and verify

Clone your fork, create and activate an isolated Python environment, then run:

python -m pip install ".[dev]"
topicllm --profile quickcheck --output-dir runs/check

Expected: all original-data hashes verified, the 5,872-record cohort reconstructed, 11 brands, one blank text, 5,871 nonempty analysis records and 704 discovery texts. No model calls.

Or install the Python wheel. The package is downloadable here; it is not advertised as a PyPI release.

2. Give your agent a concrete task

Read AGENTS.md, REPRODUCE.md and docs/protocol.json.
Verify the original Study 1 inputs. Run discovery in a new output directory.
Explain the topics, outliers and differences from the reported study.
Prepare the next steps and their API costs for me to review.
Do not invent human labels, approvals or historical outputs.

The agent handles execution and records the evidence. You review the meaning, the validation and the scientific interpretation.

3. Run discovery

python -m pip install ".[ml,dev]"
topicllm --profile study1-demo --output-dir runs/study1 --plan
topicllm --profile study1-demo --output-dir runs/study1

This uses the 704-text discovery input, 50 parameter draws and ceilings 2–25. Models and NLP resources may download on the first run; discovery makes no paid OpenAI calls. Inspect every candidate and the selected model's coverage.

4. Continue the research workflow

For naming, declare your own API budget and vote count, and set your OpenAI key privately. Run stages 2 and 3 to prepare the review packet. Two researchers approve themes; a separately annotated benchmark is required before research classification. The full analysis input has 5,871 nonempty records. The site can illustrate naming and classification without claiming that those examples are validated research findings.

Use the full execution guide for exact commands, stage artifacts and approval records. Read the methods for the scientific decisions.

Keep each result identifiable

Published dissertation findings, the recorded modern discovery run, and live demonstration responses are different evidence. Keep inputs, seeds, software versions, raw responses, review records, exclusions and outputs together. Study 2 user data are not included.
