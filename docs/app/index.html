How this app relates to the paper

This website is a visual demonstration. The guided study shows the seven-topic construction and real calculations from synthetic labels. Live examples send only fixed, fictional inputs through this site's Cloudflare Worker to OpenAI. The browser sandbox performs approximate discovery locally and uses a teaching mock. It is not the Python BERTopic implementation.

Fork the repository or download the Python package for your own corpus. An agent can prepare inputs, run checks, assemble review evidence and execute approved analysis; researcher interpretation and independent validation remain explicit checkpoints.

Reading the terminals

Each stage streams its work to a terminal panel: $ lines echo the command being executed with its exact parameters; › lines report steps; · lines are configuration detail; ✓ lines confirm completed computations; ! lines are warnings; the ▸ line at the bottom is live progress. The status on the right reads exit 0 when a stage completes cleanly — and gate refused when Stage 4 declines to scale an unvalidated classifier.

What each mode means

Study walkthrough: the published seven-topic map and a calibrated synthetic calculation. Its category assignments are known from the generator, not discovered by a fitted model. Rounded prevalence matches by design.

Exploratory workspace: a local teaching exercise using synthetic or uploaded data and a mock provider. Browser preprocessing, UMAP, clustering and topic reduction differ from the Python BERTopic implementation. Its results must not be described as a rerun of the dissertation.

Python pipeline: the maintained research implementation. Its fixes, seeds and modern dependencies differ from the original S1–S3 supplements. Record versions, model identifiers, inputs, stopwords and outputs; a seed alone is not a reproducibility guarantee.

Prepare a research corpus

Upload a UTF-8 CSV with a tweet or text column and optional ISO date values (YYYY-MM-DD). Remove blank text and resolve duplicates according to a documented protocol. Browser discovery is limited to 6,000 documents because clustering uses quadratic memory; larger corpora belong in Python.

Validate before scaling

Use independently labeled, held-out documents that include positive examples of every theme. Check precision, sensitivity and confusion counts, as well as overall agreement. A classifier that misses every rare positive can still have very high accuracy. Generated labels and mock predictions do not establish human agreement.

Data handling

Sandbox files stay in this browser tab. The public live examples accept fixed example IDs only; they do not accept your corpus, prompts or API keys. A signed, one-day session cookie supports usage limits. Read data handling and retention. Research data belong in your approved local or institutional environment.

Cost and interruption

The guided walkthrough and local sandbox make no paid calls. Public live examples are limited to ten calls per browser session per UTC day, thirty per shared IP, and the operator's site-wide allowance. The Python workflow requires an explicit paid-call budget, records usage, and resumes completed calls from its audit ledger.
