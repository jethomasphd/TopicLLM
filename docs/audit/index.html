The visual demonstration

The demonstration uses 5,872 fully synthetic posts from fictional brands. Its guided seven-category structure illustrates how the dissertation’s seven topics became five themes. The generator is calibrated so all 15 rounded prevalence percentages match the reported table. This makes the procedure easy to follow without exposing original research records.

The example’s period counts, labels and calculated tests belong to the synthetic data. They are teaching materials, not recovered historical observations. The original study data are not distributed because of privacy and research-governance constraints.

Different data can produce different topics

Topic discovery responds to the language in the corpus. The dissertation reported seven topics. A complete new Python run on the synthetic corpus selected 21. Those are results on different data: the synthetic wording and repeated campaign templates contain their own patterns. A topic-count ceiling is an upper setting, not a requirement to return a particular number.

The guided demonstration shows the research’s conceptual structure. The measured validation record shows what the maintained software actually produced on generated data. Both are useful when their purposes are clear.

From demonstration to your research

The Python workflow retains the fitted model, topic-name ballots, review evidence, classifier checks, stable document IDs, counts, denominators and API usage. Use your own documented corpus and an independently annotated benchmark. Researchers interpret and approve the themes; agents can prepare the evidence and run the computation.

Start with the fork-and-agent workflow, then consult the methods and machine-readable protocol. The five-stage package covers topic discovery through prevalence estimation; LIWC sentiment analysis and Study 2 structural equation modeling remain separate analyses described in the dissertation.
