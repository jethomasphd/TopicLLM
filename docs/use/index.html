Run it on your own text.

This is the path from exploring the example to running your own research project. You need a CSV of texts, a research question and two independent human coding passes to check the classifier.

Fork the repository to give yourself and your coding agent a working copy of the project, then install its Python package. The commands below also work without an agent. Your corpus stays in your own environment; the website's public lab is for learning the workflow.

Start with the browser tutorial if the method is new to you. The software paper explains the design; REPRODUCE.md gives the detailed execution steps.

Pilot software. Not independently validated. Python 3.11 or newer.

  1. Install and check.

    Free, offline, and done in seconds. The check verifies the bundled tutorial data byte for byte; it doesn't judge any science.

    git clone https://github.com/jethomasphd/TopicLLM
cd TopicLLM
python -m venv .venv
# macOS/Linux: source .venv/bin/activate   Windows: .venv\Scripts\Activate.ps1
python -m pip install ".[dev]"
topicllm --profile quickcheck --output-dir runs/quickcheck

    Topic discovery needs the machine-learning extra: python -m pip install ".[ml]". It runs on your computer and makes no paid calls.

  2. Hand your agent the task.

    Paste this into Claude Code, Codex or any coding agent working in your copy of the repository.

    Read AGENTS.md and REPRODUCE.md in this repository.
Run the free quickcheck, then show me the plan and its estimated cost before any paid step.
Use my data at PATH/TO/FILE.csv; the text is in the column named TEXT_COLUMN.
Run the maintained scripts and keep every output. Never invent results.
Stop and ask me at each human step: topics, codebook, human coding, accepting the classifier.

  3. Do what only you can do.

    • Read the posts behind the clusters before accepting a topic solution.
    • Write and approve the codebook with a second researcher: definitions, inclusions, exclusions, and a rule for posts that fit several themes.
    • Have two people code a random sample separately, without seeing the model's answers, then resolve their differences.
    • Accept or reject the classifier after reading its errors. Passing the 85% target is necessary, not sufficient.

Your data, in one CSV.

One row per document. You need a text column and an ID column; dates are optional unless you want separate discovery and measurement periods, as the tutorial does.

ColumnRequiredWhat it holds
text (any name)YesThe document. Name it in your config with "text_column".
id (any name)RecommendedA stable, unique identifier. Set "id_column".
dateOnly for time windowsYYYY-MM-DD, used by "discovery_window" and "target_window".

Start from the example configuration, point it at your file, and ask for a plan. The plan counts records and paid calls and gives a rough cost before anything runs.

cp examples/your-data-config.json my-config.json
# edit input_csv, text_column, id_column, domain_context
topicllm --profile research --config my-config.json --stages all --plan

Set your own stopwords with "stopwords_file"; the default list was written for Twitter. Paid steps refuse to run without an explicit --budget-usd, and keys stay in your environment, never in the config.

What it cost in the tutorial.

OpenAI GPT-4o calls, at recorded list prices. Topic discovery is free; it runs on your machine.

StepCallsCost
Naming: 500 votes for each of 12 topics, plus two discarded attempts9,808$3.80
Choosing the classifier on 100 practice posts100$0.41
The held-out check on 250 posts250$1.02
Classifying all 26,239 first-term posts26,263$107.24
Total36,421$112.47

Classifying the full corpus is the expensive step, and in research it only happens after the check passes. A smaller naming budget (100–200 votes per topic) usually shows the same leading names.
